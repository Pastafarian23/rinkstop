## Why the gaps exist (verified by API probe)

### Test 1: NHL Highlightly endpoint `/players/{id}` (e.g. 8471679 Crosby, 8478402 McDavid)
- All return HTTP 200 with `[]` (empty array)
- Conclusion: **the individual player-detail endpoint is returning no data for any ID we test, even famous ones**. The list endpoint (`/players?limit=N`) does work but only returns `{id, logo, fullName}` — no position, no jersey, no birth info.

### Test 2: `/players/{id}/statistics?season=2023` (same famous IDs)
- HTTP 200, `[]` empty.

### Test 3: `hockey.highlightly.net/players/{id}` (the alternate hockey host)
- HTTP 404 for all our IDs.

### Test 4: `/players?teamId=<NCAA_team_id>` (Yale id 15068)
- HTTP 200 with `{"message":"...", "statusCode": ...}` — i.e. error response, no roster.

### Conclusion about the data source
**The Highlightly NHL/NCAAH API is currently not returning player-detail data via the per-id, stats, or team-roster endpoints. Only the list endpoint works, and the list endpoint doesn't include position/jersey/birth data.**

The backfill script (`scripts/backfill-nhl-players.js`) was reading the per-id endpoint, getting `[]`, mapping `mapPlayerToRow([]) → null`, and the row never got updated. For NHL players, *most* of the data was already populated by an earlier successful pass — that's why "done" coverage is high. The NCAA players never got their position filled because:
- The NHL endpoint returns `[]` for them.
- The hockey endpoint returns 404.
- The list endpoint doesn't carry position.
- The team-roster endpoint returns an error.

There is no current API path to backfill the missing NCAA positions, and the missing NHL data (the 1,906 missing `birth_date` etc.) is also currently blocked at the source.
