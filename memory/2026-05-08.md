## Telegram DM Delivery Issue — FIXED

### Problem
Arnel's direct messages (DMs) to the Telegram bot were not receiving replies consistently. Group messages worked fine.

### Root Cause
Two issues:
1. **Missing user binding:** openclaw.json had 12 bindings (all groups), zero bindings for user-level DMs (peer kind "user", id 6543104235)
2. **Config auto-revert:** Gateway's config health monitor flagged the modified config as "invalid" and automatically restored from backup, removing the user binding

### Fix
1. Copied the clobbered config (openclaw.json.clobbered.2026-05-08T19-35-45-796Z) which had 13 bindings including the user binding, back to openclaw.json
2. Killed old gateway processes
3. Restarted gateway with correct config
4. Verified: 13 bindings (12 groups + 1 user), gateway health = OK

### How to add user binding in future
```bash
# Edit openclaw.json, add to bindings array:
{
  "match": {
    "channel": "telegram",
    "peer": {
      "kind": "user",
      "id": "6543104235"
    }
  },
  "agentId": "main"
}
```
Or use the clobbered config as base if gateway reverts it.

### Workaround when config reverts
- Use `message` tool with action=send, channel=telegram, target=6543104235 for guaranteed delivery
- This bypasses normal reply routing
