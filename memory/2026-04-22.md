## Gateway Pairing Issue - ROOT CAUSE & FIX

### Problem (Same as 2026-04-21)
- Gateway shows "pairing required" error
- `paired.json` resets to {} after restart
- Subagent sessions fail
- This is a KNOWN BUG in OpenClaw - GitHub issue #69284

### Root Cause (GitHub #69284)
- The gateway's `paired.json` file resets to {} after restart or during operation
- The gateway fails to auto-approve its own local client
- New pairing requests accumulate in `pending.json` but are never auto-approved
- This is an architectural issue in OpenClaw (not yet fixed in v2026.3.2 or v2026.4.14)

### Fix Applied (2026-04-22 02:00 UTC)
1. Manually added pending device to `paired.json` (same fix as 2026-04-21)
2. Gateway now shows "RPC probe: ok"

### Permanent Solution - Monitoring Script
Created `/root/.openclaw/workspace/scripts/gateway-health-monitor.sh` that:
- Checks gateway health every 5 minutes
- Checks if pairing is broken (paired.json empty or pending.json has devices)
- Auto-repairs by copying pending device to paired.json
- Sends alert to C-Suite chat if gateway is down

Added to system crontab:
```
*/5 * * * * /root/.openclaw/workspace/scripts/gateway-health-monitor.sh
```

### Why Previous Upgrades Didn't Help
The user upgraded from 2026.3.2 to 2026.4.14 but the bug persists because:
- This is a known unfixed bug in OpenClaw (issue #69284)
- The upgrade contained other fixes but not this specific pairing persistence issue

### Prevention
- The monitoring script now runs every 5 minutes
- If pairing breaks, it auto-repairs within 5 minutes
- This should prevent future downtime from this issue
